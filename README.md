# DorXmoon — сайт-визитка

Статический сайт: HTML + CSS + JS, без сборки, без сервера, без зависимостей.
Открывается двойным кликом по `index.html`, кладётся на любой хостинг как есть.

Языки: **EN по умолчанию** + RU, у каждого свой адрес (`/` и `/ru/`).
Тема оформления: **светлая по умолчанию**, переключается в шапке (выбор запоминается).
Портфолио редактируется в `admin.html` и раздельное для RU и EN.

---

## Как посмотреть сайт у себя

**Проще всего:** двойной клик по `index.html`. Работает всё, включая переключатель языка.

**Ближе к боевому:** двойной клик по `ЗАПУСТИТЬ ЛОКАЛЬНО.cmd` — поднимет сервер и откроет браузер.
Тогда адреса будут ровно как на хостинге:

```
http://localhost:8080/            EN
http://localhost:8080/ru/         RU
http://localhost:8080/admin.html  редактор портфолио
```

Закрыть чёрное окно = выключить сервер.

## Где что лежит

```
index.html            разметка (текста в ней нет — только каркас)
css/style.css         оформление; вся палитра и ритм в :root
js/app.js             движок; трогать обычно не нужно
data/
  site.config.js      ← ГЛАВНЫЙ ФАЙЛ: язык, контакты, вкл/выкл и порядок секций
  i18n.js             ← все тексты интерфейса, EN и RU рядом
  content.js          ← содержимое блоков «Почему я», «Что делаю», «Стек», «Сотрудничество»
  projects.js         ← РАБОТЫ (сейчас пусто; правится через admin.html)
img/works/            скриншоты работ
media/reviews/        видео-отзывы и их постеры
admin.html            редактор портфолио (не в меню, noindex)
tools/build-langs.js  сборщик языковых страниц
ЗАПУСТИТЬ ЛОКАЛЬНО.cmd  локальный сервер одним кликом
```

Принцип один: **разметку не трогаем, правим данные.**

## Как добавить работу — через редактор

Открой `admin.html` (двойным кликом или по адресу выше).

1. Положи скриншот в `img/works/`, например `alpha.jpg` (примерно 1200×750).
2. `+ Работа` → заполни поля на русском.
3. Кнопка **RU → EN** копирует тексты во вторую языковую вкладку — дальше просто
   переведи их. Есть и обратная, **EN → RU**.
4. Галочки **«Показывать на»** решают, где работа видна: только на русской версии,
   только на английской или на обеих. Сняты обе — работа нигде не показывается,
   это черновик.
5. `↑ ↓` — порядок на сайте, `⧉` — копия работы, `✕` — удалить.
6. **Скачать projects.js** → положи файл в `data/`, заменив старый. Обнови сайт.

Правки хранятся черновиком в браузере, поэтому закрытая вкладка ничего не теряет.
Пока файл не скачан и не положен в `data/` — на сайте изменений нет.

**Про «скрытость» админки, честно.** Страница не в меню, закрыта от индексации
(`noindex` + `robots.txt`), по ссылкам её не найти. Но настоящей защиты у неё нет
и быть не может: это статический сайт, пароль проверять некому. Защита ей и не
нужна — страница ничего не меняет на сервере, она только собирает файл, который
ты кладёшь руками. Понадобится реальный вход по паролю — это уже сервер, а не
GitHub Pages.

Руками править `data/projects.js` тоже можно — формат простой, шаблон в шапке файла.
Порядок в массиве = порядок на сайте.

Пока массив пустой — на месте блока показывается аккуратная заглушка
«Кейсы готовятся» с кнопкой в Telegram, а не дырка в вёрстке.

Поля `challenge` / `solution` / `result` можно оставить пустыми (`''`) —
в модалке они просто не появятся. `cover: ''` — будет плашка-заглушка вместо картинки.

## Как выключить или переставить секцию

`data/site.config.js`, массив `sections`:

```js
{ id: 'works', enabled: false, nav: true }   // секция и пункт меню исчезнут
```

Порядок строк в массиве = порядок секций на странице. Нумерация (`01`, `02`, …)
пересчитывается сама.

## Как поменять текст

Любую фразу интерфейса — в `data/i18n.js`, один ключ = одна фраза на двух языках.
Содержимое блоков (боли, услуги, стек, условия работы) — в `data/content.js`,
там каждая карточка это объект с `en` и `ru`.

Ключ `hero.role` — единственный, где разрешён HTML (`<b>`), он подставляется
через `data-i18n-html`. Остальные вставляются как текст.

---

## Как поменять цвета

`css/style.css`, самое начало файла: блок `:root` — тёмная тема (она основная),
блок `:root[data-theme="light"]` под ним — светлая. Больше цвета нигде не заданы.

## Языки и адреса

`site.com/` — английская версия, `site.com/ru/` — русская. Это настоящие папки,
а не `?lang=ru`: на статическом хостинге переписывать адреса некому, а поисковик
видит две отдельные страницы.

Файл `ru/index.html` **генерируется** из корневого `index.html`:

```bash
node tools/build-langs.js
```

`ЗАПУСТИТЬ ЛОКАЛЬНО.cmd` вызывает сборку сам, так что локально ты никогда не
смотришь на устаревшую русскую страницу.

Эта же команда проставляет **метки версий** (`?v=хэш`) на все css/js. Зачем:
GitHub Pages отдаёт статику с кэшем до 10 минут — правишь стиль, а в браузере
ещё старый, и кажется, что правка не приехала. Меняется файл — меняется хэш —
браузер обязан скачать заново. **Поэтому перед пушем на прод запускай сборку**,
даже если правил только `data/*.js`.

Часть контента отличается по языкам намеренно, а не переводом:
секция «Продвижение» (Яндекс, SEO, органика) есть только на RU — задаётся полем
`langs` в `data/site.config.js`. Отдельные карточки тоже умеют жить на одном языке,
у них своё поле `langs` в `data/content.js`.

## Тема оформления

По умолчанию **тёмная**. Переключатель рядом с EN/RU, выбор запоминается в браузере.
Тема ставится инлайн-скриптом в `<head>` до первой отрисовки — иначе светлая тема
моргала бы тёмной.

## Заметки по реализации

- **Моушн** сделан по правилам Emil Kowalski (`github.com/emilkowalski/skills`):
  анимируются только `transform` и `opacity`; кривые кастомные
  (`--ease-out: cubic-bezier(.23,1,.32,1)`), `ease-in` не используется нигде;
  всё под 300 мс; нажатие даёт `scale(.98)`; используются `transition`, а не
  `@keyframes` (их можно перехватить на полпути); стаггер появления 40 мс;
  hover закрыт за `@media (hover:hover)`, чтобы не срабатывал по тапу на телефоне;
  `prefers-reduced-motion` убирает движение, оставляя прозрачность.
- **Вёрстка** — одна колонка, работы списком, а не плиткой; моноширинные ярлыки
  и нумерация секций.
- Данные вставляются через `textContent`, а не `innerHTML` — случайный `<` или `&`
  в описании работы не сломает страницу.
- Файлы данных подключены обычными `<script>`, а не `fetch(JSON)` — поэтому сайт
  работает и с `file://`, без локального сервера.

## Виджеты кейса — «что сделано КРОМЕ сайта»

Внутри окна кейса живут раскрывающиеся блоки со скриншотами: карты и поиск,
веб-админка, бот как CMS. Закрыты по умолчанию — кейс читается текстом, а
доказательства открываются по желанию; клик по снимку открывает его крупно,
с зумом колесом/пинчем и перетаскиванием.

1. **Скриншоты** класть в `img/works/<проект>/`, именами латиницей, JPG до
   1600px по ширине (`ffmpeg -i in.png -vf "scale='min(1600,iw)':-2" -q:v 4 out.jpg`).
   Миниатюра показывает кадр целиком (`contain`), вертикальные снимки не режутся.
2. **Описать блок** — поле `widgets` у работы в `data/projects.js` или редактор
   `admin.html` → «Виджеты» (добавить/переставить/удалить и блок, и каждое фото).
3. **Аудитория** — `langs: ['ru']` прячет блок с английской страницы. Так сделано
   с карточкой в Яндексе и с 152-ФЗ: иностранному заказчику они ничего не говорят.
   В админке это галочки EN/RU у каждого виджета, отдельно от галочек работы.

## Как добавить демо-видео работы

Горизонтальная запись показывается в рамке ноутбука, вертикальная — в рамке
телефона рядом с ним. Редактор `admin.html` → «Демо» читает выбранный файл
прямо в браузере (никуда не загружая) и сам решает, куда его записать.

- **ПК:** родное разрешение окна, ужимать нельзя — буквы 12px мылятся необратимо.
- **Телефон:** 440–540px по ширине, пропорция берётся из самой записи.
- CRF 28–33, `-movflags +faststart`, **звук оставлять** (`-an` сделает немым и
  окно с просмотром, а не только превью). Ориентир — 3–5 МБ на минуту.
- Мобильная запись подключается только после того, как ПК-запись реально пошла,
  а на экономном соединении не грузится вовсе.

## Как добавить видео-отзыв

Отзыв — это видео в рамке телефона плюс ссылки, по которым его можно проверить.

1. **Пережать видео.** Оригинал с телефона весит 20–30 МБ, посетителю такое не
   отдают. Вертикальное 9:16, ffmpeg:

   ```bash
   ffmpeg -i original.mp4 -c:v libx264 -crf 30 -preset slow -pix_fmt yuv420p           -c:a aac -b:a 72k -ac 1 -movflags +faststart media/reviews/имя.mp4
   ```

   `-movflags +faststart` обязателен: без него браузер начинает играть только
   после полной загрузки файла. Ориентир — 3–5 МБ на минуту.

2. **Вынуть постер** — кадр, который виден до наведения:

   ```bash
   ffmpeg -ss 45 -i media/reviews/имя.mp4 -frames:v 1 -q:v 5 media/reviews/имя-poster.jpg
   ```

3. **Субтитры.** Распознаются локально (`faster-whisper`, модель `medium`, CPU —
   на этой машине CUDA нерабочая, не хватает `cublas64_12.dll`), затем ВЫЧИТЫВАЮТСЯ
   руками: машина рвёт фразу посреди слова, а машинный перевод обрывается раньше
   конца записи. Строки переносить по **26 знаков** — экран телефона-виджета
   всего 218px, строка в 40 знаков занимает 296px и браузер рвёт её сам, заливая
   текстом пол-лица. Файлы `имя.ru.vtt` и `имя.en.vtt` рядом с видео.

4. **Водяной знак** выжигается в файл, чтобы остался и на скачанной копии:

   ```bash
   ffmpeg -i in.mp4 -vf "drawtext=fontfile='C\:/path/Inter.ttf':text='DorXmoon':   fontsize=34:fontcolor=white@0.34:borderw=1:bordercolor=black@0.28:   x=(w-text_w)/2+((w-text_w)/2)*sin(2*PI*t/23):   y=(h-text_h)/2+((h-text_h)/2)*sin(2*PI*t/31)" ... out.mp4
   ```

   Периоды 23 и 31 секунды несоизмеримы, поэтому траектория не повторяется —
   надпись плавает «случайно», но без рывков, которые даёт `random()`.
   Путь к шрифту — только латиницей: кириллица в пути ломает разбор фильтра.

5. **Добавить запись** в `window.REVIEWS` (конец `data/content.js`) — по образцу
   уже лежащего там отзыва. Пути пишутся ОТ КОРНЯ сайта (`media/reviews/...`),
   `../` для страницы `/ru/` движок подставляет сам.

6. Пересобирать языки не нужно: `data/*.js` общие для обеих версий.

**Как это ведёт себя.** Подписи под телефоном нет намеренно — кнопка Play на
экране и полоска-индикатор внизу говорят сами за себя. Наведение мышью
запускает видео БЕЗ звука — браузер
разрешает автозапуск только немым. Клик открывает модалку, где видео идёт со
звуком и с контролами (клик — жест пользователя, после него звук разрешён).
На телефоне наведения нет, поэтому кнопка Play видна всегда, а тап сразу
открывает модалку.

**Поля корпуса задаются `padding`, а не `margin` у экрана.** С margin рамка
выходила неравномерной: у обычного `<div>`-корпуса вертикальные margin ребёнка
схлопываются наружу, и сверху-снизу поле обнулялось, тогда как слева-справа
оставалось (горизонтальные margin не схлопываются никогда). Симптом читается
именно так: «по бокам нормально, сверху и снизу видео упирается в грань».

**Экран ноутбука держим 16:10, а запись вписываем `contain`.** Пропорция записи
(2.13:1 — окно браузера, а не весь экран) превращала корпус в сверхширокий
монитор. Обратное — `cover` — срезало бы у записи шапку сайта. Поля сверху и
снизу честнее обоих зол.

**Модалка — тот же телефон, а не голое видео.** При клике корпус из карточки
«подъезжает» к экрану: FLIP-приём — большой корпус сначала ставится ровно в
размер и позицию маленького (`transform`), затем трансформация снимается, и
браузер сам играет переход. Между двумя состояниями обязателен принудительный
reflow (`void el.offsetWidth`), а НЕ двойной `requestAnimationFrame`: в фоновой
вкладке rAF не выполняется и телефон навсегда застревает в стартовом размере.

**Размытий поверх играющего видео быть не должно.** `backdrop-filter` на
подложку модалки пересчитывается композитором на каждый кадр — видео начинает
дёргаться, при этом то же видео при наведении и в полноэкранном режиме идёт
гладко (по этой разнице баг и опознаётся). Здесь подложка просто плотная, а
остальные размытия страницы гасятся классом `.vm-open` на `<html>` на время
показа. `opacity:0` слой с размытием не выключает — нужен `visibility:hidden`.

**Субтитры переключаются в плеере.** В модалку добавляются ОБЕ дорожки
(«Русские» / «English»), активна та, что совпадает с языком страницы; в превью
дорожка одна — там нет контролов, вторая была бы мёртвым грузом. У плеера снят
пункт «Скачать» (`controlslist="nodownload"`).

**Почему видео своё, а не ифрейм YouTube.** У сайта заявлен ноль внешних
доменов; плеер ютуба тянет трекеры и ломает это обещание.

## Редактор портфолио на проде (`/studio.html`)

Статический хостинг **не умеет проверять пароль** — сервера, который сказал бы
«нет», там нет. Поэтому редактор не «закрыт паролем», а **зашифрован**: файл
`studio.data` содержит `admin.html`, зашифрованный AES-256-GCM с ключом из
пароля (PBKDF2, 310 000 итераций SHA-256). Неверный пароль не отклоняется — он
просто не даёт ключа. Это настоящая криптография, а не `if (pass === '1234')`,
который читается в исходнике страницы за десять секунд.

**Чего эта защита не может:** помешать скачать `studio.data` и подбирать пароль
офлайн сколько угодно долго. Отсюда единственное требование — **длинный пароль**
(скрипт не примет короче 12 знаков). Короткий словарный подберут при любом шифре.

```bash
node tools/lock-admin.js          # спросит пароль, соберёт studio.data
git add studio.data && git commit -m "редактор" && git push
```

Сам `admin.html` остаётся только на диске (он в `.gitignore`) — на сайт уезжает
исключительно шифротекст. После КАЖДОЙ правки редактора его надо перешифровать
той же командой, иначе на проде останется старая версия.

`studio.html` и `studio.data` закрыты от индексации (`noindex` + `robots.txt`).
Пароль нигде не хранится и не восстанавливается: забыли — перешифруйте заново.

## Публикация на GitHub Pages

```bash
git init
git add .
git commit -m "DorXmoon card site"
git branch -M main
git remote add origin https://github.com/<логин>/<репозиторий>.git
git push -u origin main
```

Дальше в репозитории: **Settings → Pages → Source: Deploy from a branch →
Branch: `main` / `(root)` → Save**. Через минуту сайт будет на
`https://<логин>.github.io/<репозиторий>/`.

Свой домен — там же, поле **Custom domain** (в репозитории появится файл `CNAME`),
у регистратора добавить CNAME-запись на `<логин>.github.io`. HTTPS включается
галочкой **Enforce HTTPS**.
